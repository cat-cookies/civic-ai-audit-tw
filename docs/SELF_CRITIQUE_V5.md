# v5.0.0 自我批判與重構紀錄

## 前版主要失敗

1. 搜尋雖有詞彙門檻，仍缺少「問題意圖、研究方法、證據類型」三層規劃，容易把資料清單誤當答案。
2. 理論頁只有名稱與提問，沒有核心主張、作用機制、適用限制與可追溯期刊文獻，學術性不足。
3. AI 直接閱讀表單與短摘要，沒有固定的主張—證據封包；模型可輸出不存在的來源名稱。
4. 摘要以段落為主，沒有原子主張、來源識別碼、推論前提與失敗條件，因此難以驗證。
5. 多模型階段由使用者手動決定，可能對簡單問題浪費免費額度，對高風險問題又低估需求。
6. 研究方法推薦只依關鍵字加分，未把理論、代表文獻與研究限制連結。

## v5 修正策略

- 先以可重現規則建立查詢計畫、核心詞、受控名稱變體、意圖、方法與推論邊界。
- 關聯概念不再當近義詞；本體分為正式名稱、縮寫、常用語形與僅供提示的相關概念。
- 建立學說—機制—診斷問題—研究方法—期刊文獻的關聯資料庫。
- 加入 Crossref 與 Europe PMC 公開中繼資料查詢；不使用 LLM 做 bibliographic metadata retrieval。
- AI 前先建立 evidence_packet；模型只能引用其中存在的 source_id、literature_id、theory_id。
- AI 輸出改為原子主張、推論帳本、法律／政策／議事／執行分流與不確定性。
- 前端對模型回傳的來源識別碼做白名單驗證；不存在的引用會被移除並降低信心。
- 自動資源模式：一般問題1次；法律、因果、比較或證據不足2次；具名高風險與零證據3次。模型失敗只在已確認零成本候選內有限重試，不轉付費。

## 尚未解決的限制

- GitHub Pages 本身無法對所有政府網站做全文跨站檢索；本地索引仍是入口與人工核准內容。
- Crossref 與 Europe PMC 提供中繼資料及相關排序，不等於研究品質評讀。
- 部分法規、裁判及政府文件需要專門API、驗證或動態網站處理。
- 期刊文獻目錄為方法與理論的代表性起點，不是系統性回顧。
- AI 推論仍須人工查看原文、日期、法源效力與研究設計。

## 發布驗收門檻

- 無來源識別碼的事實／法律主張必須標示證據不足。
- 相關概念不得以近義詞權重進入排名。
- 每一理論至少有一篇可解析DOI的代表性文獻。
- 學術API失敗不得阻止本地文獻與網站其他功能。
- 未審內容、金鑰、原始模型輸出不得進入 `_site`。


## 第二輪工程自我批判

- **自然語句切詞不足**：前一版仍可能把沒有空格的整句當成唯一詞彙，使一般民眾問句無法命中。已加入一般公共議題詞彙切分，但這不是通用中文斷詞器；未知新詞仍可能漏失。
- **文獻查詢不是品質評讀**：Crossref 與 Europe PMC 只能擴充中繼資料；期刊名稱、引用次數與排序不得自動轉換成證據等級。介面因此保留「用途、限制、研究設計仍需人工判讀」。
- **理論推薦可能形成貼標籤**：理論必須透過核心機制、診斷問題與失敗條件選用，不得只因題目出現同一名詞。推薦結果只作候選，不能當作結論。
- **免費模型並非可驗證的永久狀態**：OpenRouter 可查零價格欄位；Gemini 與 Groq 的模型清單不能證明帳戶不會被計費，因此後端改為預設停用，須人工確認方案後才啟用。
- **來源擷取有 SSRF 與重新導向風險**：已增加初始網域與最終重新導向網域雙重白名單檢查；仍須定期維護官方網域清單。
- **重複事件綁定**：即時文獻查詢後不再重新執行整頁 `bindPage()`，避免按鈕被重複綁定而造成多次呼叫。
