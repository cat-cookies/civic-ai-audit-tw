# v5 系統架構

## 一、公開展示層

GitHub Pages 提供本地搜尋、官方資料入口、理論與期刊文獻、研究方法、跨國比較、修法三版本及 XLSX 匯出。公開部署由 `scripts/build_site.py` 建立 `_site` 白名單，不包含待審資料、原始模型輸出、私人資料或金鑰。

## 二、查詢與資料層

```text
自然語句／法規／政策問題
→ 意圖辨識
→ 核心詞與受控名稱變體
→ 本地索引與官方入口
→ 文獻／理論候選
→ 查詢計畫與推論邊界
```

搜尋以相關性為必要條件，官方性只作小幅排序因素。法律名稱與條次優先採精確辨識；不完整法條不由模型猜測。

## 三、證據層

```text
原始資料
→ 來源識別碼與中繼資料
→ 日期、版本、效力與資料類型
→ 原子主張
→ 逐字引文或可定位資料範圍
→ 反證與來源衝突
→ evidence packet
```

模型只能引用 evidence packet 中存在的識別碼；前端會移除不存在的來源、文獻、理論及推論前提識別碼。

## 四、AI 工作流

- 一般題：一次綜合階段。
- 法律、比較、因果或證據不足題：規劃加綜合兩階段。
- 具名高風險或零證據題：規劃、批判、綜合三階段。

每階段使用不同 JSON 契約，避免規劃、反方審查與最終答案混成同一段文字。備援只處理技術錯誤或無效 JSON，不以多模型投票取代證據。

## 五、學術層

理論資料庫連結核心主張、作用機制、診斷問題、可檢驗命題、研究方法及代表性期刊論文。Crossref 與 Europe PMC 只用於擴充書目中繼資料，不自動產生證據等級。

## 六、虛擬後端

`backend/hf-space` 可部署為 Hugging Face Docker Space，提供模型探索、受控來源擷取、文獻 API 代理與研究／修法分析。後端採來源網域白名單、重新導向二次檢查、個資阻擋、輸入限制、速率限制及零價格模型政策。

## 七、法律、政策、政治與執行分流

- 法律：法源、權限、法律保留、明確性、比例原則、程序及救濟。
- 政策：問題建構、目標、替代方案、成本、分配及成效。
- 政治：議程、否決者、聯盟、協商及可行性。
- 執行：組織能力、第一線裁量、資訊流程、財政、人因與執行落差。

四者可以互相影響，但不得互相替代。
