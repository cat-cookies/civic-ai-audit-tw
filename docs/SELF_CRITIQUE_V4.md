# v4 自我批判、策略修正與殘餘風險

## 一、前版的核心失敗

1. **搜尋被特定歷史資料牽引**：把「議題相關」誤當「近義」，造成長照、高齡、居家服務等詞彼此過度擴張。搜尋排序因此更像專案作者的記憶，而不是一般民眾的語意。
2. **AI 只是潤稿按鈕**：前版主要把使用者文字重新整理，沒有形成研究問題、證據矩陣、法律與政策分流、替代解釋、比較法選國理由及研究設計。
3. **多模型等於多次重寫**：六個角色雖有批判名義，但缺少節能路由，容易浪費免費額度，且多模型一致仍可能是共同錯誤。
4. **修法輸出不夠可決策**：只有單一方向與文字草稿，沒有最小、權衡、制度性三種政策強度，也沒有結構化版本比較與 Excel 交付。
5. **瀏覽器 BYOK 暴露金鑰**：雖使用 sessionStorage，仍可能被惡意擴充功能或前端環境讀取；不適合公開站長期使用。
6. **一般民眾與研究者介面混在一起**：研究方法與限制在不需要時造成負擔，需要時又不夠深入。

## 二、v4 的修正策略

### 1. 搜尋：證據式詞彙排序，不做主題聯想

- 使用詞彙頻率、文件頻率、標題／標籤／本文欄位權重與多詞覆蓋率。
- 只有「正式名稱與常用縮寫」可自動展開，例如勞基法／勞動基準法、個資法／個人資料保護法。
- 高齡照護、長期照顧、居家服務不再被視為同義詞。
- 官方來源、人工覆核與證據等級只能微調已有相關性的結果，不能讓無關文件進榜。
- AI 查詢擴張不是預設功能；啟用時必須顯示擴張詞與權重。

### 2. AI：最小充分呼叫

- **節能模式**：一次結構化呼叫，完成規劃、批判與綜合。
- **標準模式**：先產生短的研究規劃，再由第二模型或第二次呼叫綜合。
- **高風險模式**：規劃、反方批判、綜合三階段；只用於法律高風險、來源衝突或指控性內容。
- 規則式搜尋、法條解析、研究方法初選、Excel 產生均不使用模型。
- 中間結果要求 JSON，限制輸出長度，避免多模型重複寫長文。

### 3. 學術性：固定研究契約

AI 輸出至少包含：

- 問題類型與核心研究問題
- 主張—證據矩陣與支持程度
- 法律形成、政策形成、政治／議事及執行分流
- 替代方案與反方解釋
- 研究方法、資料需求與識別限制
- 跨國比較的選國理由、比較維度與移植限制
- 資料缺口、限制、信心與下一步

### 4. 修法：三版本決策支援

- A 最小修正：只補明確缺口。
- B 權衡修正：同步處理權利義務、程序與執行責任。
- C 制度性修正：加入跨機關、資料治理、預算、績效與定期檢討。
- 每版均呈現修正條文、現行條文、理由、優點、風險、執行需求與財政影響。
- 可下載真正的 `.xlsx`，不依賴外部試算表函式庫。

### 5. 安全後端

- 提供 Hugging Face Docker Space 範本，將金鑰放在 Space Secrets。
- 後端只接受公開資料，限制來源網域、檔案大小與文字長度。
- HTML／PDF 內容視為不可信證據，不允許其中的指令改寫系統提示。
- 免費模型即時發現；價格、額度或政策不明即停止，不轉付費。

## 三、殘餘風險

1. 靜態網站不能自行證明官方資料是否最新，仍需實際 API 契約測試與定期更新。
2. Gemini 與 Groq 的帳戶是否屬免費層，程式無法從模型清單完全證明；應使用未綁定付款的獨立專案或帳戶。
3. OpenRouter 的模型開發者與實際推論供應商是不同層次，必須在後端設定明確供應商白名單。
4. Hugging Face 免費 Space 可能休眠、限流或變更硬體政策，不可視為正式服務水準。
5. AI 仍可能誤讀來源；正式發布前須逐項核對原文、日期、法律效力與引文範圍。
6. 純前端 Excel 產生器為最小 OOXML 實作，支援文字表格與基本格式，不取代完整試算表套件。

## 四、公開前驗收門檻

- 搜尋測試須證明無關官方入口不會因身分加分進榜。
- 一般好奇問題不得依賴使用者過去資料。
- AI 回覆缺少來源或限制時不得標示為完成研究。
- 修法 AI 未取得現行條文時不得生成確定條文。
- Excel 檔須可解壓、含四張工作表及有效 OOXML 關係檔。
- 後端須拒絕個資、非白名單來源及未授權請求。
